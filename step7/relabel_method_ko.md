# Step 7 리라벨링 방식 정리 (팀원 공유용)

작성: 김민성 (Step 5, 7 담당) · 2026-11-19

## 한 줄 요약

학습 부분 5,535개를 LLM이 읽고 0/1과 확신도(1~3)를 붙였습니다. 그중 **기존 라벨과 다르고 확신도가 3인 604행만** 학습 라벨을 LLM 라벨로 바꾸고, 같은 모델을 다시 학습해서 **바뀌지 않은 검증 라벨**로 F1을 비교합니다.

## 1. LLM 라벨링 (학습 부분만)

- 입력: 학습 부분 5,535개에서 라벨을 뗀 파일을 200줄씩 28개로 나눈 것 (`chunk_01~28`, 마지막만 135줄). **검증 부분은 넣지 않았습니다.** 내용은 `id | 트윗` 형식입니다.
- 모델: opencode의 기본 서브에이전트 모델로, LLM이 스스로 `DeepSeek V4.1 Flash Free (opencode/deepseek-v4.1-flash-free)`라고 보고했습니다. 직접 지정한 것이 아니라 기본 설정이므로, 보고서에 URL과 함께 적기 전에 opencode 설정에서 확인합니다.
- 작업 방식: 청크 1개당 서브에이전트 1개, 4개 배치로 나눠 순서대로 실행했습니다. 모두 같은 지시문을 썼고 `prompt.txt`에 있습니다.
- 판정 기준: 실제 재난·사고·긴급 상황(뉴스, 현장, 피해·구조 포함) = 1 / 비유·농담·작품명·광고·일상·정치적 의견·가정·역사적 언급 = 0. 트윗 안의 정보만 보고 판단하게 했습니다.
- 출력: `id,label,confidence`, 입력 순서 유지. 규칙 기반 키워드 분류기는 쓰지 않았고, LLM이 읽고 판단한 결과입니다.

### 형식 검증과 재작업

- 28개 파일 모두 형식(`^\d+,(0|1),[1-3]$`), 줄 수, id 순서가 입력과 일치하는지 확인했습니다. 최종 `labels.csv`는 5,535줄, 고유 id 5,535개, 형식 오류 0건, 양성 1,196개(21.6%)입니다.
- **01번 청크는 결과가 뒤섞여** ("What's up man?"이 1, 확신도 3 등) LLM 메인 세션이 200줄을 직접 다시 라벨링했습니다. 나머지 27개 청크는 표본 점검(0으로 분류된 20개, 1로 분류된 18개)에서 문제를 찾지 못해 그대로 썼습니다.

## 2. LLM 라벨을 어디까지 믿는가 (제 표본검사)

LLM 라벨에는 정답이 없어서, 제가 **LLM 라벨을 보지 않고** 30개를 직접 읽었습니다. 방향(0→1, 1→0)과 확신도(1, 2, 3)의 6칸에서 칸마다 5개씩입니다.

| LLM 확신도 | 제 판단과 일치 | 비율 | 95% 구간 |
|---|---|---|---|
| 3 | 9 / 10 | 90% | 0.55~1.00 |
| 2 | 3 / 10 | 30% | 0.07~0.65 |
| 1 | 6 / 10 | 60% | 0.26~0.88 |
| 전체 | 18 / 30 | 60% | 0.41~0.77 |

- 이것은 "제 판단과 LLM의 일치율"이지 진짜 라벨에 대한 정확도가 아닙니다. 표본이 작아서 구간이 넓습니다.
- 위 기준(LLM 라벨을 보지 않고 직접 판단)으로 30개를 확인했을 때 **확신도 3은 10개 중 9개가 제 판단과 일치해 거의 맞았습니다.** 그래서 확신도 3은 믿을 만하다고 보고 그대로 진행합니다. 확신도 2(3/10)와 1(6/10)은 일치율이 낮거나 불안정해서 쓰지 않습니다.
- 그래서 **확신도 3만 사용**하기로 정했고, 이 기준은 실험 결과를 보기 전에 `src/config.py`(`RELABEL_MIN_CONFS = (3,)`)에 고정했습니다.
- 확신도 3이 틀린 예: id 10718 ("Got in a car wreck... lol", 라벨 0)은 LLM이 1(확신도 3)이라 했지만 개인 농담이라 LLM이 틀렸습니다.

## 3. 리라벨링 실험 (코드)

- 대상: LLM 라벨이 기존과 다르고 확신도 ≥ 3인 학습 행 **604개** (0→1이 17개, 1→0이 587개). 거의 전부 양성을 음성으로 바꾸는 방향입니다.
- 바꾸는 것: **학습 라벨만**. 검증 라벨, 분할, 전처리, 시드, 모델 설정은 그대로입니다.
- 모델: baseline, 모델 A, 모델 B를 각각 바뀐 학습 라벨로 다시 학습합니다 (각 모델의 기존 학습 함수를 그대로 호출).
- 보고하는 값: 검증 F1(바뀌지 않은 검증 라벨 기준)의 원래 값, 리라벨링 후 값, 차이. 예측 양성 비율도 함께 기록합니다.
- 코드: `src/relabel.py`, 호출은 `src/main.py`, 설정은 `src/config.py`, 입력은 `step7/llm_labels.csv`. 결과는 `results.json`의 `step7.relabel.llm_conf_ge_3`에 들어갑니다.
- 실행: `python src/main.py`. `step7/llm_labels.csv`가 없으면 이 단계는 건너뜁니다.
- 해석 기준: 차이가 약 0.01 안팎이면 노이즈로 봅니다 (Step 5에서 쓴 기준과 같음).

## 4. 팀이 알아야 할 점

1. **주 결과는 바뀌지 않았습니다.** 과제 규칙상 Step 7은 선택 실험이고 주 결과의 학습 라벨은 건드리지 않습니다. 제출하는 `submission.csv`와 Step 3 표는 원래 라벨로 만든 값입니다.
2. **과제 문구와 방식이 조금 다릅니다.** 과제는 "Step 5에서 주장한 라벨을 학습 부분에서만 고쳐라"입니다. 우리는 그 5개가 아니라 LLM이 확신도 3으로 지적한 604개를 바꿉니다. 그래서 보고서에 "5개 사례만으로는 학습 5,535개에 거의 영향이 없어, LLM으로 후보를 넓히고 표본검사로 기준을 정했다"고 이유를 적어야 합니다.
3. **1→0 편향 위험이 있습니다.** 587/604가 양성을 음성으로 바꾸는 방향이라 모델이 양성을 덜 예측할 수 있습니다. 이 때문에 예측 양성 비율을 같이 기록합니다. F1이 오르든 내리든 같은 방식으로 보고합니다.
4. **LLM 사용 공개.** 보고서 9번 "AI 및 외부 자료"에 LLM 모델명, 용도(학습 부분 1차 라벨링), 사용한 서비스를 URL과 함께 적습니다. 비어 있으면 "아무것도 안 썼다"는 뜻이 됩니다.
5. **제출물.** zip에는 `src/*.py`, `report.pdf`, `results.json`, `README.md`, `submission.csv`만 넣을 수 있고 데이터는 못 넣습니다. `step7/llm_labels.csv`는 데이터 파일이라 zip에 못 들어갈 가능성이 큽니다. 이 경우 코드는 파일이 없으면 건너뛰므로, `results.json`에 Step 7 결과가 있어도 TA가 재현은 못 합니다. 이 점을 보고서와 README에 적을지 팀이 정해야 합니다.
6. **설명 책임.** AI가 쓴 코드를 그대로 내는 것은 금지이고, 모든 멤버가 제출한 코드를 설명할 수 있어야 합니다. `src/relabel.py`는 짧으니 한 번 읽어 보세요.

## 5. 한계

- LLM 라벨은 정답이 아닙니다. 확신도는 모델의 자기 평가이고 보정된 확률이 아닙니다.
- 표본검사는 30개뿐이고 한 사람(저)의 판단입니다.
- 01번 청크는 다른 청크와 라벨링 방식이 다릅니다 (메인 세션이 직접 작성).
- 검증 부분은 LLM으로 점검하지 않았고, 검증 라벨은 끝까지 바꾸지 않았습니다.
